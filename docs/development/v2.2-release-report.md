# v2.2 private sync implementation report

V0.2.2 adds an optional encrypted snapshot service for one person using the private web app and Mac executable across devices. The existing treasury calculations, SQLite schema, workbook import, JSON backups, and public demo remain in their prior layers. See the [release summary](../release-notes-v0.2.2.md) for the user-facing changes.

## Implemented

- Private web build (`dist-private`) that checks cloud credentials before opening its IndexedDB working copy.
- Mac executable cloud connection in Settings, using the same snapshot API while retaining its local SQLite profile and offline editing.
- Client-side AES-256-GCM encryption, guarded uploads with `If-Match`, a last-synced local hash, explicit conflict choices, local safety copies before cloud replacement, and a 30-second/visibility retry check.
- Append-only server snapshot versions, list and restore controls, token authorization, explicit CORS origins, atomic head writes, a 32 MiB upload limit, and a Dockerfile for a single persistent service instance.
- Guidance for a provider-independent HTTPS deployment and backups of the server volume.

## Deployment status and remaining checks

The Docker image is running on Railway with one replica, a persistent volume, and the HTTPS private web app at `https://personal-treasury-production.up.railway.app/`. The public `/healthz` endpoint returned `{"status":"ok"}` on 2026-09-26, and Railway reported a successful deployment of the v2.2 branch. The service health check path is `/healthz`.

Railway's current Backups tab says creating scheduled volume backups requires Pro. On this plan, there is no scheduled volume backup; the [deployment guide](../guide/railway-sync.md) calls for complete JSON exports stored in encrypted storage outside Railway. App snapshot versions remain on the same volume and do not cover volume loss.

Browser end-to-end verification used Chrome at phone width; iOS Safari was not exercised. The Mac executable was packaged, but its cloud connection was not manually exercised in the native window against the deployed HTTPS service. A real Mac-to-phone sync and a recoverable off-Railway backup should be checked before relying on the hosted service for the only copy of personal data.
