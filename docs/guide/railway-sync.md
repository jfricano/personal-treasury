# Host the private sync service on Railway

Railway is one hosted option for the provider-independent service. Its [Hobby plan](https://docs.railway.com/pricing) currently has a $5/month minimum that counts toward resource usage; usage above that is billed separately. Review its pricing before creating a paid project.

The steps below deploy **one** service instance. [Railway starts with one replica by default](https://docs.railway.com/overview/advanced-concepts); to verify, open the service's **Settings → Scale → Regions** and confirm the count is `1` in one region. The snapshot writer serializes changes within that process, so do not scale it to multiple replicas against one volume. Keep changes staged until the source, volume, variables, and domain are configured, then deploy them together.

1. Create a Railway project and connect this repository's `codex/v2.2` branch as one service. Set `RAILWAY_DOCKERFILE_PATH=sync-server/Dockerfile` in its variables and keep the repository root as the build context. Railway documents [custom Dockerfile paths](https://docs.railway.com/builds/dockerfiles).
2. Attach one [persistent volume](https://docs.railway.com/volumes) mounted at `/data`. The image starts as root only to set the mounted directory's ownership, then runs the Node process as `node`. Keep one replica.
3. Add service variables: `PT_SYNC_TOKEN` (a freshly generated 64-character hex token from `openssl rand -hex 32`), `PORT=8787`, and `PT_ALLOWED_ORIGINS` (the final HTTPS app origin plus `tauri://localhost,http://tauri.localhost,https://tauri.localhost`). The image already sets `PT_SYNC_DATA_DIR=/data`, `PT_STATIC_DIR=/app/dist-private`, and `PT_SYNC_HOST=0.0.0.0`. Keep the token out of the repository and frontend build variables. [Railway variables](https://docs.railway.com/variables).
4. Generate a Railway domain under Public Networking. If asked for a target port, enter `8787`, matching the `PORT` variable. Railway provides HTTPS automatically. Add that exact `https://…` origin to `PT_ALLOWED_ORIGINS` and set the service health check path to `/healthz`. Review all staged changes, then click **Deploy**. [Railway public networking](https://docs.railway.com/networking/public-networking).
5. Schedule [daily volume backups](https://docs.railway.com/volumes/backups). App version history protects against a mistaken edit; volume backups protect against loss or corruption of the hosted storage. Also keep occasional complete JSON backups outside Railway.
6. If your existing treasury data is in the Mac app, connect it first under **Settings → Cloud sync** using the HTTPS URL, token, and a new sync passphrase. Repeat the passphrase for the first upload and wait for **Up to date**. Then open the HTTPS URL on the phone and connect with the same token and passphrase. Wait for **Up to date** before editing on either device.

No private financial data needs to be pushed to GitHub or placed in Railway variables. The server stores client-encrypted snapshots on the volume. Moving to another host means copying the data directory, updating the app URL, and resolving the first connection choice if the new URL has no remembered local baseline.
